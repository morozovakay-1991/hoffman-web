# Review instructions

## Контекст проекта

hoffman-web — сайт личного кабинета (Next.js) для пользователей hoffman:
регистрация/вход, оформление и управление подпиской, источник данных об
аккаунте для мобильного приложения. Backend — hoffman-backend (Laravel).
Архитектура авторизации — BFF-прокси: Next.js Route Handler хранит сессию в
httpOnly cookie и сам подставляет Bearer-токен в запросы к Laravel; клиентский
JS токен backend'а не видит напрямую.

## Что считать Important (🔴)

- Bearer-токен backend'а или другой секрет утекает в клиентский бандл/ответ,
  видимый в браузере (нарушение BFF-архитектуры — токен должен оставаться
  только на сервере Next.js).
- Защищённый роут (личный кабинет, история платежей, смена пароля) доступен
  без проверки сессии на сервере — если проверка только на клиенте, это
  Important, а не Nit: серверный рендер/API всё равно отдаст данные.
- IDOR — запрос к данным (подписка, платежи, профиль) по id без проверки, что
  это данные текущего пользователя.
- Чекаут выбирает не того платёжного провайдера для страны/валюты (должно
  быть Stripe вне России, CloudPayments для России) или пропускает
  подтверждение выбора пользователем.
- httpOnly cookie выставлен без нужных флагов (Secure, SameSite) или сессия
  не инвалидируется корректно при выходе/смене пароля.
- Персональные данные (email, история платежей) уходят в логи или в клиентский
  JS там, где им не место.

Всё остальное — стиль, структура компонентов, именование — не выше 🟡 Nit.

## Не проверять — уже покрыто CI

- ESLint/Prettier, типы TypeScript.
- Сам факт "тесты прошли" — проверяй, покрывает ли новый тест реальный
  сценарий, а не просто рендерит компонент.

## Лимит на нити

Не больше 5 🟡 Nit в одном ревью, остальное — одной строкой в сводке.

## Обязательно проверять

- Новый защищённый роут проверяет сессию на сервере (Route Handler/middleware),
  а не только редиректит на клиенте при отсутствии данных.
- Запросы к Laravel API идут через BFF-прокси, а не напрямую с клиента с
  токеном на руках.
- Новые страницы следуют структуре `app/(public|auth|dashboard)/`.
- Изменения в чекауте/биллинге проверены для обоих провайдеров и обоих
  сценариев страны (Россия / не Россия).

## Сводка

Начинай сводку ревью с краткого итога вида "2 критичных, 3 nit" и веди с
"критичных проблем нет", если находок уровня Important нет.
